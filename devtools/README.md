# X2D II 开发工作台

这是一套可运行的本地开发工具，不是相机固件，也不授予候选安装资格。

## 启动

双击 `Launch.cmd`，打开 http://127.0.0.1:8765。也可运行 `python -B devtools/app.py`。主服务使用 Python 标准库，不下载依赖、不要求管理员。相机识别只查询 Windows 设备元数据；机内读取和实时日志需要用户显式启动，使用已研究的固定只读连接，不自动开启 ADB、切 USB 模式、提权或更改机身日志配置。

页面提供：

- 工作台：读取当前候选宿主观察、历史全量检查真实进度及失败记录。历史结果不代表新候选通过。
- 界面实验室：原厂 QML 与隔离扩展候选的实际桌面 Qt 画面，鼠标点击、Escape返回、截图、停止。
- 任务协作：负责人、状态、阻塞说明和协调记录；每秒同步、本地原子保存、并发修改冲突检测。
- 代码与改动：只读原厂扩展源码及当前隔离候选差异。
- 实时日志：预览、当前固定本地检查、历史检查的实际末尾输出；可开始/停止本工具自己创建的检查，不控制历史进程。
- 相机与模型：固定只读 PnP 识别、本地模型检测、后台任务、实际输出；识别失败不会冒充已连接。

相机识别先用一次固定查询取得当前 USB 身份、状态及驱动服务；父设备与其他可选详情使用本地 Windows 配置管理器读取，不再做 24 次串行 CIM 属性查询。详情缺失不会抹掉已观察到的 USB 连接，缺驱动也与“未检测到”分别显示。USB 识别仍不等于已建立机身调试或拍摄连接。每次点击重新查询，不沿用上一轮连接结果。

本次故障的永久本地回归要求保存在 `REGRESSION_GATES.json`。正式固件回归登记仍被正在执行的历史检查冻结，登记待合并，不能把本地工具测试当作固件发布通过。

## Codex 插件与后台模型

插件源在 `devtools/plugin/`，仓库本地目录在 `.agents/plugins/marketplace.json`。使用官方支持的兼容插件清单与 stdio MCP，六个固定工具：状态、相机识别、本地模型列表、提交任务、读取输出、读取菜单源码。安装后需要在新会话加载；本会话已有工具不会仅因文件落盘而自动增加。

后台使用当前实际存在的 `http://127.0.0.1:18107/v1` 服务，也可在页面选择其他明确的本机回环端口；禁用代理、重定向和外网地址，不接受密钥。任务只发送用户任务与选中的一份菜单源码；不会传输照片、原始相机日志或整个系统树。任务和输出原子保存在 `devtools/data/models/jobs.json`。服务在运行时可独立处理已排队任务；关闭浏览器不停止队列，关闭服务中断未完成任务，重启不自动重复。

`等待 Codex 审查` 是协作角色，不绑定任何模型版本，使用 Codex 当前选择的模型。本地模型的输出不会执行、不自动改源码、不控制相机、不自行标记审核通过。本版本尚不提供自动唤醒 Codex、无人值守自动合并或机身调试/拍摄通道。它也不是新的相机固件。

插件包装依据：[OpenAI 官方插件文档](https://developers.openai.com/plugins/build/plugins)。这是个人本地开发插件，未发布到公共目录；不是 OpenAI 或哈苏官方插件。

## 七部分代码与机内操作

系统代码按界面与菜单、拍摄控制、硬件采集与控制、图像与算法、保存与持久化、基础系统、通信与维护分类。目录只接受固定文件 ID，显示真实路径、来源、原文、SHA256 和差异；反编译分析、schema 和二进制元信息不等于完整原厂源码。大文件仅显示大小等信息，不能把截取的一段称为全文。

保存仅向 `devtools/data/code-drafts/` 原子提交本地副本，并检查原文哈希和副本 revision，原厂提取物及历史工程不修改。首次保存失败保留隔离的未提交 generation，允许安全重试；已发布元数据损坏会拒绝覆盖。保存的草稿不会自动加入构建、桌面预览或机身部署。

机内接入固定于既有 `192.168.42.2:30303` 只读路线，连接前后核对实际身份和 boot。七部分机内读取当前是有限摘要、启动文本与挂载状态，不是任意文件或全部机内代码。USB 设备出现不代表这条通道已开通。失败显示实际原因，不自动切换到其他调试路线。

部署、开机加载配置激活、恢复已接原有 PreparedOperation 分派，网页不能提供 shell、路径、资格或批准布尔值。默认没有可信本地执行上下文，当前候选也未全链路资格验证，三项写操作保持不可用。开机配置激活不是当前 GUI 已加载的证明；真正安装仍要满足项目发布要求和最终用户批准。恢复使用保存的原安装清单及独立恢复资格，不依赖失败的新候选通过。

## 实时拍摄时间线

打开「拍摄时间线」→「开始实时读取」，随后在相机上正常拍照。第一份日志只作起点；后续按七部分呈现新增事件，可选拍摄请求的前后日志窗口并展开原文、机身时刻、接收时刻、显式帧号/请求号及本地原包证据位置。没有观察到的部分标为“未观测”，不是“没运行”。不会触发快门，也不读照片像素。

固定读取 `/blackbox/camera/log/cam.log`，首次从开启会话时的EOF建立基线，再按已确认字节位置分块补读，每块最多64 KiB。范围绑定打开的文件描述符及前后boot/inode/size；Base64严格还原原始字节，拼完整行后严格解码UTF-8。64字节旧锚点检查已读位置附近的覆盖。元数据读取引用打开fd的shell `/proc/$$/fd/3`，而不是未继承fd的stat子进程。保留完整原生回包、退出码、规范编码和严格范围校验；head正常截断tail引发的SIGPIPE不能单独判失败。积压时立即补读，追上后间隔一秒，每块仍检查停止、时间及磁盘额度。

已建立的会话遇到明确连接失败、超时或EOF时，最多自动重试120秒，保留parser、游标、锚点和半行；重连重新核对身份，并检查实际范围的boot/inode。部分回包只保留证据，不作成功数据；已发现重复完成标记、损坏回包、非零退出、权限拒绝、来源变化或本地落盘失败不能被当成断线重试。停止立即取消重试等待。该功能是同一进程内的接续，不是持久化检查点恢复：程序重启、手动新会话及重试耗尽后的重新开启仍建立新EOF基线，旧会话原证据保留，不承诺补回间隔日志。

确认轮转/截断后，不再跳过新来源开头，先建立空的0字节解析起点再补读。旧文件已知未读范围和未完成半行记入独立连续性证据；尚未实现从轮转归档恢复旧尾，缺口不会因追上新文件被清除。同inode锚点改写无法判定新旧，明确记缺口并重新建立EOF基线，不能从头重放旧请求。重建时积压显示未知，不显示假零。原会话之前的日志、旧文件已移走的未读字节、机内未记录的函数，以及锚点以外的同inode改写仍不能保证覆盖。

原始范围先落盘，所有分类事件再写入原子发布的历史段；页面最近200条只是快速视图，不是会话总数。七部分卡片按本会话累计观测计数，来源变化另保留当前来源计数。可以查看已存记录、向更早/较新记录翻页和返回实时，刷新不覆盖历史页；当前仅接入本次工作台进程当前监控会话的历史浏览，之前会话文件仍留在磁盘。选中起点已移出最近列表的拍摄窗口时，明确显示不完整。跨块半行完整后，事件保留整行覆盖的每个原包路径、字节起点和长度；单行最大64 KiB、证据范围最多128块，超过边界明确失败。显示最后成功读取时间、读取速度、积压趋势和重连次数，这不是毫秒级全函数追踪或照片完整性验证。

单次会话额度仍为8小时或2 GiB本地证据，先到者停止，可手动开新会话；页面显示已用时长与容量。原始采样分文件保存在电脑，监控内存只保留序号及有限事件，不积累每次查询预览。2 GiB计入原始回包、字节编码文本和元数据，不仅是日志原文字节；编码及原始协议副本会增加占用，实际磁盘分配还包含文件系统开销。普通证据写入前检查至少1 MiB剩余空间余量，不足时停止、不删除旧记录；外部进程同时耗尽磁盘仍可能导致写入失败，不能保证终态文件必然可写。持续生产速度超过补读速度仍会增加积压，轮转或覆盖时仍可能丢日志，不能承诺无损或把短时间真实采样称为已实测连续8小时。

AF/AE活动可能属于预览，GraphMgr配置不是JLS编码完成，`-1002`等待也可能发生于空闲，文件写入成功日志不替代照片读回校验。拍摄请求窗口按日志先后划分，不将时间相邻的帧、预览和后台事件强行关联为同一张照片，也不认定照片完整落盘。实时读取期间其他设备操作共用同一任务锁，不并发占用机身连接。原包只保存在本机，不发送给本地模型或外部服务。

## 桌面界面边界

复用本工程现有 Qt 6.8.2、原厂编译 MainScreen、原厂 GridView/FramedItem 和宿主缓存桥。它不是 QEMU、不是 ARM64 执行，也不是机身屏幕。相机服务、部分图像类型为宿主夹具边界替代，数值不是实际硬件读数。启动/页面渲染成功不能证明拍摄、对焦、SSD写入、启动配置或回滚。未配置原厂素材/宿主运行库时，明确报错，不显示伪造画面。

画面与预览日志只输出 `devtools/data/preview/`，任务保存到 `devtools/data/board.json`。固定“本地菜单加载与失效检查”复用已有检查器，会新增 `build/menu-ready-development-20261008/runs/<uuid>/` 独立结果，主机进程输出同时保存于 `devtools/data/jobs/`；不覆盖旧结果或共享构建文件。不改原厂 `.cim`、冻结源码、正式回归登记、照片或校准。停止只针对自有进程。同一数据目录只允许一个工作台服务；多个浏览器窗口共享该服务。

## 协作者实时登记

页面任务状态是协作者登记，不是自动识别的 AI 子智能体状态。另一位 AI/人工协作者可使用：

```
python -B devtools/task.py entry --owner Codex --state doing --note "正在检查真实点击与返回"
```

任务板按当前服务器 revision 检测冲突；陈旧客户端返回409，不能静默覆盖他人的调整。会话token每次启动更新，连接仅绑定127.0.0.1。不要把端口暴露到局域网/公网；同一Windows账户下的进程仍可能读取本地token，这不是多用户权限隔离系统。任务完成登记不等于发布门槛通过。
